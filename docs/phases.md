# Plan por fases

Al cerrar cada fase: compila, tests pasan, README actualizado y resumen de qué se hizo y cómo probarlo.

| Fase                             | Alcance                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **0 · Diseño**                   | Este paquete de documentación: arquitectura, modelo de datos, permisos, ADRs, wireframes, registro de tratamiento. _Requiere aprobación._                                                                                                                                                                                                                                                                 |
| **1 · Base**                     | Monorepo, Docker Compose de desarrollo, auth + sesiones + MFA + códigos de recuperación, bloqueo y rate limiting, alta de usuarios por Admin, RBAC granular, catálogos de área y depósito, auditoría, layout con design tokens TML, CI (lint, test, build, audit), Dependabot.                                                                                                                            |
| **2a · Ticketera**               | Formulario guiado por tipo (problema / pedido / propuesta de mejora o automatización / pedido de integración), estados, asignación, prioridad, comentarios públicos/internos, registro de tiempo, motor de SLA con horario hábil y feriados, monitor de SLA, notificaciones en la campana, "Mis tickets", bandeja de IT, configuración de SLA/horario/feriados/cierre automático (deshabilitado), e2e. ✅ |
| **2b · Ticketera (cont.)**       | Adjuntos con storage S3 (MinIO) y pipeline ClamAV, worker con BullMQ (el monitor de SLA y el cierre automático pasan a jobs), `EmailSender` SMTP apagado por defecto, texto enriquecido (TipTap + sanitización) con pegado de capturas.                                                                                                                                                                   |
| **3 · Problemas**                | Vinculación de tickets, resolución en bloque, sugerencia de duplicados (FTS + trigramas). ✅                                                                                                                                                                                                                                                                                                              |
| **4 · Mejoras**                  | Creación desde tickets o problemas, kanban, lista, detalle con historial y comentarios internos, cierre en bloque de tickets al implementar o descartar. ✅                                                                                                                                                                                                                                               |
| **5 · Clientes e integraciones** | Maestro de clientes y contactos, integraciones con "cómo funciona" (texto enriquecido con historial), cotizaciones por proveedor, documentos de integración, derivación ticket → integración, vista de proyecto, importador del F50 (CSV/Excel). La biblioteca entra en versión básica (subir, versionar, ver). ✅                                                                                        |
| **6 · Conocimiento**             | Artículos con versiones y ficha de error, biblioteca completa, extracción de texto + OCR, fragmentos, búsqueda con número de página, visor PDF, carga masiva, promoción desde tickets/problemas.                                                                                                                                                                                                          |
| **7 · Dashboard**                | Indicadores de tickets, propuestas, problemas, mejoras, clientes e integraciones con filtros y drill-down.                                                                                                                                                                                                                                                                                                |
| **8 · Producción**               | Compose de producción, Caddy, hardening del VPS, backups cifrados con restauración probada, exportación/anonimización por titular, checklist OWASP ASVS L2 y RGPD, runbook de incidentes, definición de ubicación del VPS.                                                                                                                                                                                |

## Fuera de alcance (por ahora)

- IA: chatbot, embeddings, pgvector. La base queda preparada ([ADR 0011](adr/0011-ai-readiness-chunks.md)).
- Entrada de tickets por mail. Queda preparada ([ADR 0013](adr/0013-input-channels-extensibility.md)).
- Políticas de retención automáticas.
- Modo oscuro (los tokens quedan listos).
- SSO con Google Workspace (contemplado en el modelo: solo usuarios ya existentes).

## Decisiones cerradas (Fase 0)

| Tema                                    | Decisión                                                                                                                                                                                                                               |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SLA antes del triage                    | Prioridad provisoria = urgencia del usuario. Al fijar prioridad IT, se recalculan vencimientos.                                                                                                                                        |
| Ticket derivado a mejora                | Estado `DERIVED_TO_IMPROVEMENT`, SLA detenido. Se cierra cuando la mejora queda Implementada **o** Descartada, con comentario público que explica qué se hizo o por qué se descartó. Cierre en bloque de todos los tickets vinculados. |
| Ticket derivado a integración           | Estado `DERIVED_TO_INTEGRATION`. Se cierra cuando la integración queda Finalizada o No realizada.                                                                                                                                      |
| Sistemas                                | Cuatro sistemas como categorías: WMS, TMS, TYT (carga de pedidos de clientes) y Routing (ruteador).                                                                                                                                    |
| Sector del ticket                       | Depósito, área (Comercial, Calidad…) o ninguno.                                                                                                                                                                                        |
| Pedidos de integración                  | Pueden ser con clientes, expresos u otros. La categoría queda fija en Integración.                                                                                                                                                     |
| Tipos de ticket                         | Soporte, Automatización, Integración y Acceso. Cada tipo tiene sus preguntas y sus categorías. El tipo es independiente del sistema/categoría.                                                                                         |
| SLA de automatizaciones e integraciones | Solo 1ª respuesta: 2 días hábiles (configurable), medido como indicador con alertas. Sin SLA de resolución.                                                                                                                            |
| Estados de integración                  | Pendiente de relevar → Pendiente de cotizar → Cotizada → En desarrollo → Finalizada \| No realizada (con motivo).                                                                                                                      |
| Proveedores                             | Catálogo editable (Interno, Molipa, SGL; se puede sumar TYT). Compartido entre mejoras e integraciones.                                                                                                                                |
| Cotizaciones                            | Varias por integración, una marcada como elegida.                                                                                                                                                                                      |
| Documentación de integración            | Campo "Cómo funciona" (texto enriquecido con plantilla e historial) + documentos adjuntos tipados, guardados en la biblioteca.                                                                                                         |
| Depósito / Área                         | Catálogos editables; el usuario tiene valores por defecto.                                                                                                                                                                             |
| Cierre automático                       | Configurable, deshabilitado por defecto.                                                                                                                                                                                               |
| Adjuntos                                | 25 MB por adjunto; 100 MB por documento de biblioteca.                                                                                                                                                                                 |
| Retención                               | Sin políticas automáticas. Solo exportar/anonimizar usuario a mano.                                                                                                                                                                    |
| Usuarios                                | ~20 usuarios del sistema (de 60 empleados).                                                                                                                                                                                            |
| Repo                                    | GitHub privado.                                                                                                                                                                                                                        |
| AAIP                                    | La base no está inscripta. El registro de tratamiento sirve como insumo para el trámite.                                                                                                                                               |
